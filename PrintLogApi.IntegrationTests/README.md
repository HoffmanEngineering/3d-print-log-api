# PrintLogApi Integration Tests

Integration tests for the PrintLogApi using ASP.NET Core's `WebApplicationFactory` with SQLite in-memory database.

## Project Structure

```
PrintLogApi.IntegrationTests/
├── Controllers/
│   ├── PrintsControllerTests.cs       # Tests for /api/Prints endpoints
│   └── DatabaseDiagnosticsTests.cs    # Tests for data seeding verification
├── CustomWebApplicationFactory.cs     # Test server configuration
├── IntegrationTestSeeder.cs           # Test data seeding
├── TestAuthHandler.cs                 # Test authentication handler
└── README.md
```

## Running Tests

```bash
# Run all integration tests
dotnet test PrintLogApi.IntegrationTests

# Run with verbose output
dotnet test PrintLogApi.IntegrationTests -v n

# Run with code coverage (generates HTML report)
./coverage.ps1

# Run with coverage and open report in browser
./coverage.ps1 -Open
```

## Test Infrastructure

### CustomWebApplicationFactory

Configures the test server with:
- **SQLite in-memory database** instead of SQL Server
- **Test authentication scheme** that bypasses Auth0
- **Automatic test data seeding** after host creation

```csharp
public class MyTests : IClassFixture<CustomWebApplicationFactory>
{
    private readonly HttpClient _httpClient;

    public MyTests(CustomWebApplicationFactory factory)
    {
        _httpClient = factory.CreateClient();
    }
}
```

### IntegrationTestSeeder

Seeds minimal test data for integration tests:
- 1 test user with OAuth ID `auth0|test-integration-user`
- 2 printers
- 3 filaments
- 5 prints

**Important:** User and printer IDs are auto-generated by SQLite. Access them via:
- `IntegrationTestSeeder.TestUserId` - Internal user ID (populated after seeding)
- `IntegrationTestSeeder.TestPrinterId` - Internal printer ID (populated after seeding)
- `IntegrationTestSeeder.TestUserOAuthId` - OAuth user ID (constant)

### TestAuthHandler

Custom authentication handler for testing authenticated endpoints.

**How it works:**
1. Checks for `X-Test-User-Id` header containing an OAuth user ID
2. Looks up the internal user ID from the database
3. Creates a `ClaimsPrincipal` with proper claims (`Upn` and `NameIdentifier`)

## Making Requests

### Anonymous Requests

```csharp
// Simple GET request
var response = await _httpClient.GetAsync("/api/Prints/summary?userId=1");

// With JSON deserialization
var model = await _httpClient.GetFromJsonAsync<PagedList<PrintSummaryDTO>>(
    "/api/Prints/summary?userId=1");
```

### Authenticated Requests

```csharp
// Create request with auth header
var request = new HttpRequestMessage(HttpMethod.Get, "/api/Prints/summary");
request.Headers.Add(TestAuthHandler.TestUserIdHeader, IntegrationTestSeeder.TestUserOAuthId);

// Send request
var response = await _httpClient.SendAsync(request);

// Deserialize response
var model = await response.Content.ReadFromJsonAsync<PagedList<PrintSummaryDTO>>();
```

### POST/PUT Requests with JSON Body

```csharp
var request = new HttpRequestMessage(HttpMethod.Post, "/api/Prints");
request.Headers.Add(TestAuthHandler.TestUserIdHeader, IntegrationTestSeeder.TestUserOAuthId);
request.Content = JsonContent.Create(new AddPrintDto { Title = "Test" });

var response = await _httpClient.SendAsync(request);
```

## Writing New Tests

### Basic Test Structure

```csharp
public class MyControllerTests : IClassFixture<CustomWebApplicationFactory>
{
    private readonly HttpClient _httpClient;

    public MyControllerTests(CustomWebApplicationFactory factory)
    {
        _httpClient = factory.CreateClient();
    }

    [Fact]
    public async Task MyEndpoint_ReturnsSuccess()
    {
        // Arrange
        var request = new HttpRequestMessage(HttpMethod.Get, "/api/MyEndpoint");
        request.Headers.Add(TestAuthHandler.TestUserIdHeader, IntegrationTestSeeder.TestUserOAuthId);

        // Act
        var response = await _httpClient.SendAsync(request);

        // Assert
        Assert.Equal(HttpStatusCode.OK, response.StatusCode);
    }
}
```

### Adding Test Data

If you need additional test data, modify `IntegrationTestSeeder.cs`:

```csharp
private static void SeedMyEntities(PrintLogContext context, long userId)
{
    context.MyEntities.Add(new MyEntity
    {
        Name = "Test Entity",
        CreatedById = userId
    });
    context.SaveChanges();
}
```

Then call it from `Seed()`:
```csharp
public static void Seed(PrintLogContext context)
{
    var user = SeedUser(context);
    TestUserId = user.Id;
    // ... existing seeding ...
    SeedMyEntities(context, user.Id);
}
```

## Environment Configuration

The tests use the `IntegrationTesting` environment, which:
- Skips database migrations (uses `EnsureCreated()` instead)
- Uses SQLite in-memory database
- Uses test authentication instead of Auth0

Configuration is loaded from `appsettings.IntegrationTesting.json` in the main project.

## Troubleshooting

### "Services for database providers" Error
If you see an error about multiple database providers, ensure all EF Core services are removed before adding SQLite. This is handled in `CustomWebApplicationFactory`.

### Data Not Persisting Between Requests
The SQLite connection must stay open for the entire test lifetime. The factory handles this by keeping `_connection` open until disposal.

### Authentication Not Working
Ensure you're adding the correct header:
```csharp
request.Headers.Add(TestAuthHandler.TestUserIdHeader, IntegrationTestSeeder.TestUserOAuthId);
```

The header name is `X-Test-User-Id` and the value should be the OAuth ID (e.g., `auth0|test-integration-user`).
